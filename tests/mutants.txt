# Mutants that must be caught.
#
# Each record names a single-line edit to production source and the test that
# must fail once it is applied. `scripts/check-mutants.sh` applies each one to a
# scratch copy of the tree and reports any mutant the named test does not kill.
#
# The point is not to find defects in the implementation — the suite and
# independent review do that. It is to prove the *tests* are load-bearing. Every
# entry below was written after a real surviving mutant exposed a test that
# could not fail:
#
#   - #18 shipped a canary test whose constant was never passed to anything;
#   - #24's scope-escalation test used a fixture that satisfied two rules at
#     once, so either rule alone could rot unnoticed;
#   - #26 had four survivors, including a permission test that compared each
#     mode constant with itself;
#   - #28's review fixes shipped with no tests at all, so three new fail-closed
#     configuration rules had nothing that would notice if they stopped
#     holding. Those entries were written from the fix rather than from a
#     survivor, which is the cheaper order to discover the same thing in.
#
# Format: blank-line-separated records of `key: value`. Required keys are
# name, file, find, replace, scope and test; `runs` (default 3) repeats a
# mutant that races, and every run must fail. `occurrence` selects which match
# to replace when `find` is not unique in the file.
#
# Adding an entry: pick the smallest edit that removes the property, not the
# largest. A mutant that breaks compilation proves nothing.
